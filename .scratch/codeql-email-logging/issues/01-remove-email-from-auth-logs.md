# 01 — Stop logging user emails during the auth status check

> *This was generated by AI during triage.*

**Status:** ready-for-agent

**Source:** CodeQL code scanning alerts #6–#13 (`cs/exposure-of-sensitive-information`, medium) — https://github.com/pkirilin/food-diary/security/code-scanning

## Agent Brief

**Category:** bug
**Summary:** The auth status check writes the signed-in user's email to the application log; remove it

**Current behavior:**
`GetAuthStatusQueryHandler.Handle` reads the email claim (`Constants.ClaimTypes.Email`) from the authenticated principal and writes it into every `LogInformation` message it emits — on token check, on success, on expiry, on missing tokens, on refresh failure, on user-info failure and, via the private `AuthenticatedWithNewTokens(..., string? userEmail)` helper, after a successful refresh. The handler runs on every auth status check, so each check writes the email to the log at least once. Serilog writes these to stdout at the default `Information` level, where self-hosters may forward them to log aggregators. CodeQL reports this as 8 alerts against that one handler.

**Desired behavior:**
The handler emits the same log events at the same points and levels, but no log message carries the user's email or any other claim value from the principal. Messages still say what happened (e.g. "Access token expired. Attempting to refresh token...", "Could not refresh token"). Auth outcomes are unchanged: same `GetAuthStatusResult`, same sign-in/sign-out side effects, same token refresh.

Lowering the log level is not a fix — CodeQL flags the logger call regardless of level.

**Key interfaces:**
- `GetAuthStatusQueryHandler.Handle` — drop the `{UserEmail}` template placeholder and argument from every log call; the local `userEmail` variable should disappear if nothing else uses it
- `AuthenticatedWithNewTokens` — drop its `userEmail` parameter
- `GetAuthStatusQuery` / `GetAuthStatusResult` — no change

**Acceptance criteria:**
- [ ] No logger call in `GetAuthStatusQueryHandler` receives the user's email, directly or through a helper parameter
- [ ] `rg -n -i "email" --type cs src/backend/src | rg -i "log"` returns no logger calls that pass an email
- [ ] Every log event the handler emitted before still exists, at the same level, in the same branch
- [ ] `dotnet build` passes with no new warnings, and `dotnet test` passes (component tests need Docker — see CLAUDE.md)
- [ ] After merge, CodeQL alerts #6–#13 close on the next `main` scan (verify on the code scanning page; don't dismiss them by hand)

**Out of scope:**
- Adding a replacement user identifier (hashed email, user ID) to the logs
- Log redaction infrastructure (`Microsoft.Extensions.Compliance`, Serilog destructuring policies)
- Other code scanning alerts (#1–#5: workflow permissions, test mock hostname regex)
- Changing Serilog configuration or log levels

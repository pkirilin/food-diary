# 01 — A cleared nutrition field is not auto-filled by a suggestion

> *This was generated by AI during a grilling session.*

**Status:** ready-for-agent

**Source:** found while grilling the Zod 4 migration ([spec](../../zod-4-migration/spec.md), research §6.3); reproduced on 2026-10-04 with a throwaway component test. Design: [Product Form — AI Nutrition Suggestions](../../../docs/superpowers/specs/2026-07-06-product-nutrition-ai-suggestions-design.md).

## Agent Brief

**Category:** bug
**Summary:** The suggestion fill rule treats a nutrition field the user typed into and then cleared as filled, so it is skipped

**Current behavior:**
In the product form, type `5` into Protein, delete it, then click Suggest on Calories. Every untouched empty nutrition field receives its suggested value; Protein stays empty.

`NutritionValueInput` is a plain text field, so `Controller` stores `event.target.value` and a cleared field holds `''`. The fill rule in `useNutritionSuggestions` (`applyEligible`) checks `getFieldValue(field) === null`, so `''` counts as filled. Saving is unaffected: `NutritionValueSchema` turns `''` into `null` on submit.

The design spec encodes the same gap: *"'empty' for a macro means the current value is `null`"* (Behavioural cases → Notes). It describes the initial form state, not a field the user has cleared.

**Desired behavior:**
A nutrition field counts as empty when its value is `null` or a string that is blank after trimming, matching what `NutritionValueSchema` treats as no value. Everything else in the fill rule is unchanged: the clicked field is always overwritten, a `null` suggestion is always skipped, and a field holding any other text is left alone.

**Key interfaces:**
- `entities/product/lib/useNutritionSuggestions.ts` — the emptiness check in `applyEligible`
- `getFieldValue` — after the Zod 4 migration it returns `string | number | null`; if this lands first, widen it as part of the fix
- `ProductInputDialog.fixture.tsx` / `ProductInputDialog.test.tsx` — the regression test belongs in the existing `nutrition suggestions` describe block

**Regression test** (failed against the current code; the same arrangement with Protein left untouched passed):

```tsx
test('a cleared field is filled after clicking another field suggest button', async () => {
  const user = userEvent.setup();
  const categories = givenCategories('Dairy');
  givenNutritionSuggestion({ calories: 402, protein: 25, fats: 33.1 });

  render(
    givenProductInputDialog()
      .withCategoriesForSelect(categories)
      .withProduct({ name: 'Cheddar cheese', category: categories[0] })
      .please(),
  );

  await whenDialogOpened(user);
  await whenNutritionPanelExpanded(user);
  await whenProteinChanged(user, '5');
  await user.clear(screen.getByPlaceholderText(/protein/i));
  await whenSuggestClicked(user, /suggest calories/i);

  await thenCaloriesEventuallyHasValue('402');
  await thenProteinEventuallyHasValue('25');
});
```

Prefer a fixture helper (e.g. `whenProteinCleared`) over the inline `user.clear` to match the file's given/when/then style.

**Acceptance criteria:**
- [ ] The regression test above passes, and fails if the emptiness check is reverted
- [ ] A field containing only whitespace is also filled by another field's suggestion
- [ ] Existing `nutrition suggestions` tests still pass (filled fields untouched, clicked field overwritten, `null` suggestions skipped)
- [ ] The design spec's definition of "empty" is corrected to `null` or blank text
- [ ] `yarn build`, `yarn test` and `yarn lint` pass in `src/frontend`

**Out of scope:**
- Normalising the form value to `null` on change (e.g. in `NutritionValueInput`): it changes what every consumer of the field value sees, not just the fill rule
- Treating `0` or other numeric values as empty
- Any change to the API, the prompt or the backend mapping

# 14: Warn about missing nutrition values in the new flow

**What to build:** When the owner picks a product in the old dialog, the quantity step warns "Nutrition values are missing" if the product is missing nutrition values: none of protein, fats, carbs, sugar or salt is set. The new flow never shows this warning, so such a product goes into the Meal Draft without notice. The detail screen shows the warning as an alert above the product's name and calories, and search result rows and tray rows mark the product with a small warning icon. The same alert and row indicator replace the existing ones on the index page and the meals list, so the app has one warning style. ## Agent Brief

**Category:** bug
**Summary:** Add one shared missing-nutrition alert and row indicator, show them in the multi-item flow, and move the index page and meals list onto them

**Current behavior:**
The old single-item dialog shows "Nutrition values are missing" under the picked product when the product is missing nutrition values. The multi-item flow never shows this, so such a product goes into the Meal Draft without notice. The spec's "Old dialog behaviours" table lists this as "Kept, gap".

Elsewhere the warning looks different in each place:
- The index page shows a warning `Alert` reading "Some nutrition values are missing", with MUI's default icon.
- The expanded meals-list note row shows a warning `Alert` with a smaller `WarningAmberOutlinedIcon`.
- Meal headers and meals-list note rows show a warning dot badge with no accessible name.

**Desired behavior:**
- A Product is *missing nutrition values* exactly when `productModel.hasMissingNutritionValues` returns true, which means all five optional values are `null` (see `GLOSSARY.md`). Reuse that helper and leave its condition unchanged.
- **Shared alert**: a missing-nutrition-values alert component in the product entity's UI. It's a MUI `Alert` with `severity="warning"`, the default (standard) variant, MUI's default filled warning icon, and no action button. One prop selects the case: for a single product it reads "Nutrition values are missing", and for an aggregate such as a day summary it reads "Some nutrition values are missing".
- **Shared row indicator**: a row indicator component in the product entity's UI. It's a small (about 16 px) amber warning icon, with the accessible name "Nutrition values are missing", so tests and screen readers can find it by role or label.
- **Where the indicator sits**: in a fixed column on the right of the row's text area, before the row's trailing action or calories, about 8 px from any button. Its position doesn't depend on the length of the product name.
- **Detail screen** (the quantity form for a `MealDraftProduct`): the single-product alert spans the full width above the row with the product's name, "<calories> kcal per 100 g" and the **Edit product** pencil.
- **Search result rows** (`FoundProductListItem`) and **tray rows** (`MealDraftFoodLogListItem`): the row indicator for a product missing nutrition values. The ⊕ / delete actions and the selected state behave as before.
- **Index page**: its existing alert becomes the shared alert in the aggregate case, in the same place.
- **Meals list**: the expanded note row's alert becomes the shared single-product alert, in the same place. The dot badges on meal headers and note rows become the shared row indicator.
- Every indicator follows the current product data. When **Edit product** saves values and `productUpdated` updates the Meal Draft, or a refetch updates the search results, the alert and icons appear or disappear to match.

**Key interfaces:**
- `productModel.hasMissingNutritionValues(OptionalNutritionValues): boolean`: reuse it unchanged. `foodLogModel.MealDraftProduct` already carries the `protein`/`fats`/`carbs`/`sugar`/`salt` subset as `number | null`.
- The two new components live in `entities/product/ui` and are exported from the product entity, so pages, widgets and features can all import them under FSD.

**Acceptance criteria:**
- [ ] The detail screen shows the single-product alert above the name, calories and pencil row for a product missing nutrition values, and no alert for a product with at least one optional value set
- [ ] Search result rows and tray rows show the row indicator, findable by the accessible name "Nutrition values are missing", for a product missing nutrition values, and no indicator otherwise
- [ ] After **Edit product** saves a value for such a product, the detail screen, its search result row and its tray row no longer show the warning
- [ ] The index page shows the shared alert reading "Some nutrition values are missing" under the same condition as before
- [ ] The expanded meals-list note row shows the shared single-product alert, and meal headers and note rows show the row indicator instead of the dot badge, under the same conditions as before
- [ ] No warning dot badge or `WarningAmberOutlinedIcon` alert remains for missing nutrition values
- [ ] Colocated component tests cover both shared components and each row and screen above. The mock API seed data includes a product missing nutrition values if it doesn't already.
- [ ] The spec's "Old dialog behaviours" row reads "Kept" with where it lives, and the spec's detail screen, search results and tray sections describe the warning
- [ ] Browser verification per `.claude/rules/frontend.md` passes, covering the detail screen, search results, tray, index page and meals list at phone width with a long product name

**Out of scope:**
- Changing `hasMissingNutritionValues` to an "any value missing" rule
- The old single-item dialog's caption warning
- Blocking **Add**/**Save** or any other behaviour for products missing nutrition values. The warning is informational only.
- A warning on the tray's collapsed summary row or on the Meal as a whole
